# Agent Note: 多库选择改用下拉切换

Status: implemented

## Problem

用户勾选较多数据库时，右侧 Tab 栏被挤爆：标签被截断、横向溢出，红框区域拥挤难用（截图可见 8+ 个库的 Tab 只剩几字符）。之前为多库切换引入的 Tab 在库多时反而成为负担。

## Decision

按勾选库数量自适应：

- **≤ `TABS_MAX`（6）个库**：继续用 `QFluentWidgets.TabBar`，切换快、直观。
- **> 6 个库**：隐藏 Tab，显示 `ComboBox` 下拉选择当前库（宽 320，完整显示库名）；搜索、排除、表清单等下方功能不变。

两种模式都经 `_activate_database()` 激活：Tab 点击、下拉切换、左侧点击都会同步当前库、左侧列表高亮行与表清单。切换配置或重新加载数据库时两个控件都清空；导出期间下拉同样禁用。

## Affected repositories

- `mysql-export-data` 分支 `main` commits `6e8c76b`

## Alternatives considered

**一直用 Tab + 加横向滚动/左右箭头。** 保留 Tab 交互。不选：库名仍会被截断，32 个库要滚很久，且 QFluentWidgets TabBar 的溢出表现不理想。

**一直用下拉（去掉 Tab）。** 实现最简单。不选：2–3 个库时 Tab 一键切换明显更快，用户此前也认可 Tab；按数量自适应兼顾两种情况。

**左侧数据库列表点击即切换 + 不提供右侧切换控件。** 不增加控件。不选：左侧列表同时承担勾选，点击切换和勾选容易混淆，且多库时还要滚动找库。

**下拉 + 搜索过滤框。** 适合几十个库。不选：MySQL 实例通常 <32 个业务库，下拉本身可滚动，额外搜索框收益低、界面更挤。

## Consequences

**收益：** 多库时切换控件不再溢出，完整库名可读；少量库时保留 Tab 的便捷；两种模式行为一致，激活逻辑共用。

**代价：** 多一个 UI 控件与一条阈值分支（`TABS_MAX`）；Tab 与下拉的显示状态需要在重建时同步维护；测试新增多库场景（共 112 项）。
