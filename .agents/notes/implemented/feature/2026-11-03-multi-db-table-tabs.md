# Agent Note: 多库表清单按 Tab 切换与批量排除

Status: implemented

## Problem

界面改版后（见 `../feature/2026-11-03-simplified-ui-shell.md` 与 `../architecture/2026-11-03-qfluentwidgets-ui-stack.md`），左侧库列表负责勾选、右侧表清单只显示「当前高亮库」。实际导出时用户常一次勾选多个库，问题暴露：

- 右侧一次只看到一个库的表，切库要回到左侧重新点击，多库时来回点很别扭；
- 想排除某些表时，只能逐行取消勾选，或在「正则」弹窗里按库写规则，无法快速按表名批量排除，也无法一次应用到多个库。

## Decision

右侧表清单改为「按已勾选库分 Tab」，并在每个 Tab 内提供快速排除工具：

- **Tab 与库勾选联动**：勾选几个库就出现几个 Tab（`QFluentWidgets.TabBar`），切换 Tab 即切换库；左侧点击库也会切到对应 Tab。Tab 隐藏关闭/新增按钮，避免与左侧勾选状态脱节。
- **Tab 内工具条**：表名搜索框（即时过滤）、**排除选中**（表清单支持 Ctrl/Shift 多选，一键把选中行变为仅结构）、**批量排除**（粘贴表名列表，默认应用到全部已勾选库）、正则排除（可勾选「应用到所有已勾选的库」），以及原有的全选/清空。
- **数据加载**：每个库的表清单按库缓存（`MainWindow._db_tables`），Tab 首次激活时异步加载；勾选库之后后台按顺序预取，切换 Tab 基本即时。
- **状态持久化不变**：排除仍按库写入 `config.json` 的 `databases.<db>.exclude_tables / exclude_regexes`；排除表语义不变（只输出建表语句、不导数据，正则命中行锁定并灰显）。
- **行为兼容**：`_on_tables_loaded(db, tables)`、`_store_current_db_state()`、`_render_tables()` 等内部接口保留，旧的库级排除/导出逻辑不变。

## Affected repositories

- `mysql-export-data` 分支 `main` commits `fdd25bb`

## Alternatives considered

**跨库合并成一张总表（增加「库」列）。** 所有表一次看全，搜索范围最大。不选：同名表跨库时归属容易混淆，排除操作需要看清「库+表」两列；Tab 更贴近用户「逐个库处理」的心智。

**独立「排除表」弹窗（列出所有勾选库的表）。** 排除流程集中、界面不改。不选：多一次模态往返，且排除前仍需浏览表；改成 Tab + 工具条后可以边看边排除。

**保留单库视图，只加搜索与批量按钮。** 改动最小。不选：用户反馈的核心痛点之一就是「选了多个库后右侧看起来不方便」，不解决切库成本。

**每个库常驻一个 TableWidget，用 QStackedWidget 切换。** 切换零加载。不选：控件与内存开销随库数线性增长，且多数库只导出不改表；单表格按需渲染更轻。

## Consequences

**收益：** 多库场景下切库成本从「左侧来回点 + 等待加载」降为「点 Tab」；排除表从逐行取消变为「搜索 + 多选排除」或「粘贴表名批量排除」，且可一次应用到所有已勾选库；表数据缓存后切换 Tab 即时。

**代价：** 主窗口状态变多（每库缓存、Tab 激活、加载队列），`_on_database_highlighted` 从「加载当前库」变为「联动 Tab」；勾选库时会后台预取表清单（网络往返增加，但异步且可取消关闭）；新增 5 项测试覆盖 Tab/搜索/批量排除。
