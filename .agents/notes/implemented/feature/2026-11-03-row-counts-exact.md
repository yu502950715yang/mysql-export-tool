# Agent Note: 行数自动精确统计

Status: implemented

## Problem

表清单的「估算行数」直接显示 `information_schema.TABLES.TABLE_ROWS`。InnoDB 该值是后台统计的近似值，不随增删改实时更新，视图固定为 0。用户实测发现与实际不符：开发库 34 张表里 10 张不一致、116 张里 18 张不一致（例：`sys_oper_log` 估算 157,387 / 实际 163,118；视图 `v_student` 估算 0 / 实际 30,379）。

用户要求准确行数，但**不要手动按钮**。

## Decision

当前库 Tab 渲染后**自动**在后台精确统计，不阻塞列表：

- 列表先显示带 `~` 的估算值（表头与单元格 tooltip 说明），状态栏显示「精确行数统计中…」。
- `RowCountWorker` 逐表执行 `SELECT COUNT(*)`，每完成一张就发信号更新对应单元格（去掉 `~`），工具栏显示「精确行数 N/M…」。
- 单表查询前 `SET SESSION max_execution_time=10000`；超时/失败只跳过该表（tooltip 标注原因，保留估算值），继续下一张。
- 取消：切换库 Tab / 开始导出 / 关闭窗口时 `cancel()` 用新连接 `KILL QUERY` 中断当前 COUNT，避免退出卡死；已完成的精确值保留在 `_db_tables` 缓存，`TableInfo.rows_exact` 标记是否已精确，重新进入 Tab 只统计剩余表。
- 排序仍按当前值；精确值回填后不自动重排，避免打断选择与阅读（用户再点表头即按新值排序）。
- 颜色/文案：`~` 前缀表示估算，精确值无前缀；表头由「估算行数」改为「行数」。

## Affected repositories

- `mysql-export-data` 分支 `main` commits `a492a2f`

## Alternatives considered

**手动「精确行数」按钮。** 可控、不会自动压服务器。不选：用户明确不要手动按钮。

**去掉行数列。** 最省事。不选：用户需要行数信息，只是要准确。

**保持估算并标注「约」。** 无额外负载。不选：用户明确要准确。

**一次性 `COUNT(*)` 全部库再渲染。** 简单。不选：会阻塞列表秒开，且大库耗时不可控。

## Consequences

**收益：** 行数最终是精确值，不再误导；加载仍秒开；统计在后台进行、有进度；切 Tab/导出/退出都能中断，已统计结果缓存复用。

**代价：** 自动 COUNT 会给数据库带来额外扫描负载（大表可能各需数秒，单表 10 秒超时兜底）；切换 Tab 会取消未完成的统计，回来时继续剩余表；`~` 到精确值的切换会让行数文字短暂变化；测试新增自动启动/回填/显示用例，共 110 项。
